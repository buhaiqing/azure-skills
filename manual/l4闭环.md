# L4 自动化闭环

> `auto_feedback_loop.py` 实现 Observe → Diff → Heal 的完整闭环。

## 1. 工作原理

```
Execute ──▶ Observe ──▶ Diff ──┬──▶ Heal ──▶ Done
                               │
                               │ No Match
                               ▼
                          Escalate
```

## 2. CLI 使用

```bash
python scripts/auto_feedback_loop.py \
  --skill <skill_name>              \
  --operation <operation_name>     \
  --command "<az command>"         \
  --desired-state '<json>'         \
  --max-heal-attempts <N>          \
  --trace-id <id>                  \
  --dry-run                        \
  --observe-cost                    \
  --risky
```

### 参数说明

| 参数 | 必填 | 说明 |
|------|------|------|
| `--skill` | ✅ | 技能名称，如 `azure-vm-ops` |
| `--operation` | ✅ | 操作名称，如 `vm_create` |
| `--command` | ✅ | 原始 az 命令 |
| `--desired-state` | ✅ | 期望状态（JSON） |
| `--max-heal-attempts` | ❌ | 最大修复次数（默认: 2） |
| `--trace-id` | ❌ | Trace ID |
| `--dry-run` | ❌ | 仅演练，不实际执行 |
| `--observe-cost` | ❌ | 开启成本观测 |
| `--risky` | ❌ | 跳过危险操作确认 |

## 3. Python API

```python
from scripts.auto_feedback_loop import run_with_feedback, FeedbackResult

result = run_with_feedback(
    skill="azure-vm-ops",
    operation="vm_create",
    command="az vm create --name my-vm --resource-group my-rg --image UbuntuLTS",
    desired_state={"powerState": "VM running"},
    max_heal_attempts=3,
)

# 检查结果
if result.status == "success":
    print("✅ 成功")
elif result.status == "healed":
    print("⚠️ 自动修复")
elif result.status == "escalated":
    print("❌ 升人工")
else:
    print(f"❌ 失败: {result.message}")
```

### FeedbackResult 结构

```python
@dataclass
class FeedbackResult:
    status: str           # "success" | "healed" | "escalated" | "failed"
    actual_state: dict   # Azure API 返回的原始状态
    heal_attempts: int   # 实际修复尝试次数
    trace_id: str        # 关联 trace ID
    message: str         # 人类可读摘要
    escalation: str|None # 升人工消息
```

## 4. desired_state 字段参考

| 资源类型 | JMESPath 字段 | 示例值 |
|----------|----------------|--------|
| VM | `powerState` | `"VM running"` |
| VM (旧) | `statuses[1].displayStatus` | `"VM running"` |
| AKS | `provisioningState` | `"Succeeded"` |
| Blob Container | `name` | `"my-container"` |
| Key Vault | `properties.provisioningState` | `"Succeeded"` |
| App Service | `state` | `"Running"` |
| SQL Database | `status` | `"Online"` |
| Load Balancer | `provisioningState` | `"Succeeded"` |

**如何获取 JMESPath**：

```bash
az vm show --name my-vm --resource-group my-rg --output json | jq '.powerState'
```

## 5. 自愈策略

策略定义在 `scripts/self_healing/*.json`：

```json
{
  "skill": "azure-vm-ops",
  "operations": {
    "vm_create": {
      "risky": false,
      "health_check": {
        "api": "az vm show",
        "parse_field": "powerState",
        "expected": "VM running"
      },
      "healing_rules": [
        {
          "condition_type": "field_not_equal",
          "condition_field": "powerState",
          "condition_value": "VM running",
          "heal_action": "az vm start",
          "max_attempts": 3,
          "backoff_seconds": 30
        }
      ]
    },
    "vm_delete": {
      "risky": true
    }
  }
}
```

### 内置补偿动作

| 操作 | 命令 |
|------|------|
| `vm_start` | `az vm start` |
| `vm_stop` | `az vm stop` |
| `vm_restart` | `az vm restart` |
| `aks_wait` | `az aks wait` |
| `webapp_start` | `az webapp up` |
| `keyvault_wait` | `az keyvault show` 轮询 |

## 6. 状态含义

| status | 含义 | 动作 |
|--------|------|------|
| `success` | 成功，状态匹配 | 无需操作 |
| `healed` | 自动修复成功 | 检查结果 |
| `escalated` | 修复失败，已升人工 | 查看 escalation 消息 |
| `failed` | 命令执行失败 | 修复命令后重试 |
